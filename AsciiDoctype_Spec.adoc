= Engineering Specification: AsciiDoctype

== 1. Scope & System Topology
This document defines the formal engineering specification for AsciiDoctype, a standalone Python formatting library. AsciiDoctype lowers the official, TCK-compliant Resolved Abstract Semantic Graph (ASG) produced by AsciiDoctrine into valid text-based markup specifications (HTML5 or strict XHTML).

....
[ AsciiDoctrine Resolved ASG Dictionary ] 
                   │
                   ▼ (Passed to)
[ AsciiDoctype Renderer Engine ] <─── (Assembles) ─── [ Chameleon Template Stack ]
                   │
                   ├──> HTML5 Pipeline ───> Modern Void-Tag Strings (e.g., <img>)
                   └──> XHTML Pipeline ───> Strict Self-Closing Strings (e.g., <img />)
....

== 2. Input Data Interface Specification
AsciiDoctype operates completely on the deserialized Python dictionary structures generated by AsciiDoctrine’s polymorphic `to_dict()` node method. The renderer must explicitly support the following schematic definitions:

=== 2.1 Block-Level Components

* Document: `{"name": "document", "type": "block", "blocks": [List[Dict]], "attributes": Dict, "header": Dict}`
* Section: `{"name": "section", "type": "block", "level": int, "title": List[Dict], "blocks": [List[Dict]]}`
* Paragraph: `{"name": "paragraph", "type": "block", "inlines": List[Dict]}`
* Listing: `{"name": "listing", "type": "block", "form": "delimited", "delimiter": str, "inlines": List[Dict]}`
* List: `{"name": "list", "type": "block", "variant": "unordered|ordered", "marker": str, "items": List[Dict]}`
* ListItem: `{"name": "listItem", "type": "block", "principal": List[Dict], "blocks": List[Dict]}`

=== 2.2 Inline-Level Components

* Span: `{"name": "span", "type": "inline", "variant": "strong|emphasis|code|mark", "form": "constrained|unconstrained", "inlines": List[Dict], "attributes": Dict}`
* Ref: `{"name": "ref", "type": "inline", "variant": "link", "target": str, "inlines": List[Dict]}`
* Text (Leaf Node): `{"name": "text", "type": "string", "value": str}`

== 3. Template Resolution & Search Order
The rendering system relies on a structural folder strategy managed through Chameleon's `PageTemplateLoader`.

=== 3.1 Core Bundled Paths
AsciiDoctype bundles its own canonical fallback templates inside its package distribution, divided into two distinct target subdirectories:

* `asciidoctype/core_templates/html5/`
* `asciidoctype/core_templates/xhtml/`

Each directory must contain a flat file collection mapping exactly to the schema name key parameter (e.g., `document.html`, `section.html`, `paragraph.html`, `span.html`, `text.html`).

=== 3.2 Precedence Resolution
To fulfill the requirement for flexible, themeable layout inheritance without full file system tracking overhead, the class initializer accepts an array of external path references (the intent is for this to be supplied by the orchestrator tool Golem).
The explicit template path lookup stack must execute in this exact sequence:

1. User Overrides Directory (e.g., `./my_site/overrides/`)
2. Active Theme Template Directory (e.g., Pip-installed template source path)
3. AsciiDoctype Core System Fallbacks (`html5` or `xhtml` sub-folder)

== 4. Execution Engine Architecture

=== 4.1 Recursive Rendering Engine
The implementation class initializes the Chameleon cached file environment and handles structural execution routines using a central traversal method.

[source,python]
----
import os
from pathlib import Path
from typing import Dict, Any, List, Optional
from chameleon import PageTemplateLoader

class AsciiDoctypeRenderer:
    def __init__(self, target_format: str = "html5", search_paths: Optional[List[Path]] = None):
        self.target_format = target_format.lower()
        if self.target_format not in ("html5", "xhtml"):
            raise ValueError("Target target_format must be 'html5' or 'xhtml'")
            
        # Determine internal system path fallback location
        base_dir = Path(__file__).parent.resolve()
        core_fallback = base_dir / "core_templates" / self.target_format
        
        # Build ordered search array
        self.search_paths = search_paths or []
        self.search_paths.append(core_fallback)
        
        # Initialize compiled bytecode caching container
        self.loader = PageTemplateLoader(
            [str(p) for p in self.search_paths], 
            default_extension=".html"
        )

    def render(self, node: Dict[str, Any], context: Optional[Dict[str, Any]] = None) -> str:
        """
        The central dispatch router for resolving ASG nodes recursively.
        """
        if not isinstance(node, dict) or "name" not in node:
            raise TypeError("Invalid node structure passed to rendering processor.")
            
        ctx = context or {}
        node_name = node["name"]
        
        try:
            # Look up pre-compiled template object block
            template = self.loader[f"{node_name}.html"]
        except ValueError:
            # Fall back securely to generic container handler if specific file is absent
            template = self.loader["fallback_container.html"]
            
        # Execute compiled bytecode loop passing engine pointer for recursion nested checks
        return template(node=node, renderer=self, ctx=ctx)
----

== 5. Specification Constraints & Template Blueprints

=== 5.1 The XML/HTML Injection Rule
Because leaf string components evaluate recursively up the semantic pipeline graph tree, template structures must strictly process inner node contents utilizing the `structure` modifier. Failure to provide the `structure` prefix will result in escaping valid HTML/XHTML brackets.

=== 5.2 HTML5 vs. XHTML Output Directives

* Void Element Formatting: In HTML5 specification layout files, elements such as line-breaks or metadata values must omit ending slash tokens. For XHTML specifications, all elements must explicitly close self-contained structures.
* Namespace Bindings: XHTML layouts must enforce lower-case validation criteria and apply namespace routing properties to document root wrappers.

=== 5.3 Core Template Syntax Mapping

==== paragraph.html (Shared Architectural Layout)

[source,xml]
----
<p tal:attributes="id node/attributes/id | nothing"
   class="${node/attributes/role | ''}">
    <tal:block tal:repeat="inline node/inlines" 
               tal:replace="structure renderer/render(inline, ctx)" />
</p>
----

==== text.html (Leaf Component Output)

[source,xml]
----
<!-- Text nodes emit raw value content with no surrounding layout shells -->
<tal:block tal:replace="node/value" />
----

==== span.html (Inline Styling Logic Engine)

[source,xml]
----
<tal:block tal:choose="node/variant">
    <strong tal:case="'strong'" 
            tal:attributes="class node/attributes/role | nothing"
            tal:content="structure container"><!-- Nested parsing placeholder --></strong>
    <em tal:case="'emphasis'" 
        tal:attributes="class node/attributes/role | nothing"
        tal:content="structure container"></em>
    <code tal:case="'code'" 
          tal:attributes="class node/attributes/role | nothing"
          tal:content="structure container"></code>
    <mark tal:case="'mark'" 
          tal:attributes="class node/attributes/role | nothing"
          tal:content="structure container"></mark>
    
    <!-- Fallback if variant is missing -->
    <span tal:case="default" 
          tal:attributes="class node/attributes/role | nothing"
          tal:content="structure container"></span>
          
    <metal:block define-macro="container">
        <tal:block tal:repeat="inline node/inlines" 
                   tal:replace="structure renderer/render(inline, ctx)" />
    </metal:block>
</tal:block>
----

==== section.html (Recursive Hierarchy Tree Mapping)

[source,xml]
----
<section class="adoc-section level-${node/level}" 
         tal:attributes="id node/attributes/id | nothing">
    <tal:block tal:define="heading_tag string:h${node/level + 1}">
        <!-- Dynamically interpolate heading element size securely -->
        <tal:heading tal:omit-tag="not:heading_tag" tal:attributes="tag heading_tag">
            <tal:block tal:repeat="title_node node/title" 
                       tal:replace="structure renderer/render(title_node, ctx)" />
        </tal:heading>
    </tal:block>
    
    <!-- Structural lower rendering pass over child components -->
    <div class="section-blocks">
        <tal:block tal:repeat="block node/blocks" 
                   tal:replace="structure renderer/render(block, ctx)" />
    </div>
</section>
----

== 6. Error Routing and Troubleshooting Boundaries
Because structural optimizations from AST blocks to target ASG dictionaries can drop line telemetry arrays, template runtime compilation issues could mask root execution context bugs.
If an unexpected exception fires during block layout lowering passes, AsciiDoctype must trap the base error event and wrap the stack output context into a custom diagnostic wrapper. This strategy tracks down the faulty node definition path cleanly without crashing the main application flow loop.

[source,python]
----
class AsciiDoctypeRenderingError(Exception):
    """Raised when Chameleon bytecode routines fail to resolve a dictionary node element."""
    pass

# Nested execution trap wrapped inside rendering evaluation paths
try:
    return template(node=node, renderer=self, ctx=ctx)
except Exception as err:
    raise AsciiDoctypeRenderingError(
        f"Critical rendering failure processing structural node entity: '{node.get('name', 'unknown')}' "
        f"Target Specification Pipeline: [{self.target_format}]. Base Error: {str(err)}"
    ) from err
----
