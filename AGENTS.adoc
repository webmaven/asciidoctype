== Development Environment

=== Prerequisites

* Python 3.9 or later
* `git`
* `gh` (GitHub CLI, preferred for cloning/branching)

Key runtime dependencies: `chameleon`, `asciidoctrine`, and `latex2mathml`
(used for converting LaTeX stem blocks into MathML).

=== Setup

[source,bash]
----
gh repo clone webmaven/asciidoctype
cd asciidoctype

python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate.bat       # Windows

pip install -e .[dev]
pre-commit install
pytest -v                          # should show 42+ passed
----

[IMPORTANT]
====
Never use the system `python` or system `pytest`. Always use
`./.venv/bin/pytest` — the virtual environment has the required dependencies.
====

== Test-Driven Development

AsciiDoctype uses strict Red/Green TDD:

. Write a failing test that specifies the expected behaviour.
. Run `./.venv/bin/pytest -v` to confirm it fails for the right reason (missing
  feature, not a syntax error).
. Write the minimum implementation to make the test pass.
. Run `./.venv/bin/pytest -v` to confirm all tests pass.
. Clean up and commit.

For template integration testing, use a TCK-style approach: tests should parse
raw AsciiDoc source strings using `asciidoctrine.lark_parser.parse_to_ast` and
`asciidoctrine.resolver.ASGResolver`, then render the resulting ASG through
`AsciiDoctypeRenderer` and assert on the HTML/XHTML string output. This ensures
templates are tested against real, faithful ASG structures rather than
hand-crafted mock dicts.

[IMPORTANT]
====
Do not submit a pull request without tests. Pull requests that reduce test
coverage will not be merged.
====

== Template Development

=== Checklist

When adding a new node template:

* [ ] Read the ASG node schema in `ARCHITECTURE.adoc §5`.
* [ ] Write failing tests using TCK-style integration testing (parsing AsciiDoc with `asciidoctrine.lark_parser.parse_to_ast` and `asciidoctrine.resolver.ASGResolver`, rendering the result with `AsciiDoctypeRenderer`, asserting on the HTML string output).
* [ ] Write failing tests in `tests/test_html5_<node>.py`.
* [ ] Write failing tests in `tests/test_xhtml_<node>.py` (if XHTML-specific
      behaviour exists).
* [ ] Implement `core_templates/html5/<node>.html` with no trailing newline.
* [ ] Implement `core_templates/xhtml/<node>.html` with no trailing newline.
* [ ] Verify all 42+ existing tests still pass.
* [ ] Run pre-commit checks (`./.venv/bin/pre-commit run --all-files`).
* [ ] Run coverage and confirm no regressions.
* [ ] Update `ARCHITECTURE.adoc §5` coverage status from 🔲 to ✅.
* [ ] Commit with a `feat:` prefix commit message.

=== Template Guidelines

* Use Python-style attribute access in expressions:
  `node.get('attributes', {}).get('id')` rather than TAL path expressions
  (`node/attributes/id`) which do not work with plain `dict` objects.
  TAL path syntax _is_ valid on Chameleon-provided objects (e.g.
  `repeat/item/index` on the built-in `RepeatDict`), but `node`, `ctx`, and
  all other plain-dict variables in the template namespace require Python
  expression syntax.
* Always use `structure renderer.render(child, ctx)` when emitting child
  node output. Without `structure`, HTML brackets are escaped.
* Avoid newlines inside inline element templates (span, text, ref). Chameleon
  preserves whitespace, and stray newlines produce unwanted gaps in output.
* Both `html5/` and `xhtml/` templates are required for every node.
  The XHTML variant must use self-closing void elements (`<br />`).

=== Example: Minimal Template Pair

`src/asciidoctype/core_templates/html5/quote.html`:

[source,xml]
----
<blockquote tal:attributes="id node.get('attributes', {}).get('id');
                             class node.get('attributes', {}).get('role')">
    <tal:block tal:repeat="block node.get('blocks', [])"
               tal:replace="structure renderer.render(block, ctx)" />
</blockquote>
----

`src/asciidoctype/core_templates/xhtml/quote.html`:

Same content — the XHTML `document.html` wrapper provides the namespace and
DOCTYPE; inner block templates need no XHTML-specific changes unless they
contain void elements.

== Known Chameleon Quirks

[cols="1,3",options="header"]
|===
|Issue |Fix

|`tal:choose` does not exist
|Use `tal:switch` / `tal:case` instead.

|`NameError: value` in `text.html`
|Use `node['value']` (KeyError propagates) or `node.get('value', '')`. The
`node/value` path expression fails on plain dicts in recent Chameleon.

|`NameError: container` when using `metal:block define-macro`
|Do not use METAL macros in inline templates. Inline child iteration directly
in each `tal:case` branch instead.

|Whitespace in output
|Multi-line templates introduce newlines between inline elements. Use compact
single-line templates for inline elements (`span.html`, `text.html`).

|`tal:attributes="tag heading_tag"` does not change element name
|Chameleon cannot change an element's tag name dynamically. Use separate
`<h1>`, `<h2>`, … `<h6>` elements with `tal:condition="hlevel == N"` instead.

|`modules` not available in template namespace
|In templates, `modules` is not available in the Chameleon namespace. Use `__import__('package.module').module` to import packages dynamically inside templates (used by `stem.html` for `latex2mathml`).
|===

== Project Standards

=== Code Style

* Follow https://peps.python.org/pep-0008/[PEP 8].
* Type-annotate all public functions and methods.
* Keep functions small and single-purpose.
* No global mutable state.

=== Template Style

* One template per node type, one file per pipeline.
* No CSS or JavaScript in templates — AsciiDoctype is a headless renderer.
* All attribute access defensive: `node.get('key', default)` never bare `node['key']`
  (unless a missing key should propagate as an error, like `node['value']` in
  `text.html`).

=== Documentation

* Update `ARCHITECTURE.adoc §5` when adding or changing node support.
* Update `README.adoc` Quick Start examples if the public API changes.
* All docs are AsciiDoc (`.adoc`). No Markdown files should be added.

=== Commit Messages

Follow the https://www.conventionalcommits.org/[Conventional Commits] spec:

[cols="1,2",options="header"]
|===
|Prefix |Use for

|`feat:`
|New feature, new template

|`fix:`
|Bug correction

|`docs:`
|Documentation update

|`test:`
|Tests only, no production code

|`chore:`
|Tooling, build, CI

|`refactor:`
|Restructuring without behaviour change
|===

Examples:

----
feat: implement list and listItem templates for HTML5 and XHTML
fix: handle missing attributes dict in section template
docs: document ref node schema in ARCHITECTURE.adoc
test: add coverage for xhtml listing block rendering
----

== Design Constraints (Quick Reference)

For full design rationale, see link:ARCHITECTURE.adoc[ARCHITECTURE.adoc §7 Design Constraints].

[cols="1,2",options="header"]
|===
|Constraint |Summary

|No CSS, JavaScript, or styling
|Headless renderer; markup only, styling is downstream.

|No file I/O in production code
|Only reads template files via `PageTemplateLoader`.

|No mutation of input nodes
|`node` and `ctx` dicts are read-only.

|Dual template rule
|Every node needs both `html5/` and `xhtml/` templates.

|Python-style attribute access
|Use `node.get()`, not TAL path expressions, on plain dicts. TAL paths work
on Chameleon-provided objects (e.g. `repeat/item/index`) but not on `node`
or `ctx`.

|`structure` keyword required
|Child rendering must use `structure` to prevent escaping.

|No trailing newlines in inline templates
|Chameleon preserves whitespace; inline templates must be compact.
|===
